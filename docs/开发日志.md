## 3. 2026-06-18：后端与知识库主链路

**提交：** `3b86cf6`（与前端初始化相隔数分钟）

**做了什么**

- 新增 Maven 多模块后端：`rag-doc-common`、`rag-doc-model`、`rag-doc-server`。
- 建立 7 个 Controller：用户、部门、知识库、文档、问答、工单、统计。
- 建立 MyBatis-Plus Mapper 与自定义 XML（文档、知识库、用户、分片、对话、消息、工单、统计）。
- 接入 MinIO、Qdrant、DashScope Embedding、DashScope Chat。
- 打通“上传文档 → MinIO → 文档表 → 异步解析 → 分片 → 向量化 → Qdrant → 检索问答”的主链路。
- 建立 JWT 登录与注册，密码使用 BCrypt。
- 当时使用 `JwtTokenInterceptor` + `BaseContext` / `CurrentUserUtil` 保存当前登录用户。
- 建立统一响应 `ResponseResult`、分页 `PageResponseResult`、业务码 `AppHttpCodeEnum`。
- 建立异步线程池 `documentParseExecutor`，用于解析和向量化。

**关键实现选择**

| 问题 | 处理方式 |
| --- | --- |
| 上传后解析耗时长，不能阻塞接口 | 上传只做 MinIO + 文档入库，解析和向量化通过 `@Async("documentParseExecutor")` 异步执行 |
| PDF/DOCX/TXT 格式不同 | PDF 用 PDFBox，DOCX/DOC 用 POI `XWPFDocument`，TXT 按 UTF-8 读取 |
| 文本过长无法直接向量化 | 约 500 字符分片、50 字符重叠，按段落和句末标点切分 |
| Embedding 接口单次批量有限制 | 业务层每 25 条一批，Embedding 实现内部每 10 条调用一次 |
| 不同知识库向量隔离 | 每个知识库一个 `kb_{kbId}` Collection，检索时按 `kb_id` 过滤 |
| 前后端 Long 精度 | `WebMvcConfiguration` 把 Long 序列化为字符串 |
| MinIO 存的是完整 URL | 预签名前去掉 `endpoint/bucket/` 前缀 |

**遗留问题**

- 基于拦截器和 ThreadLocal 的用户上下文，在异步线程和部分调用链中不方便复用，后续在 9 月重构。
- 文档删除只做逻辑删除，没有同步清理 MinIO 和 Qdrant。
- 解析/向量化失败没有重试机制。

## 5. 2026-09-18：权限认证重构

**提交：** `9ec9432`（37 个文件，970 行新增、371 行删除）

**做了什么**

- 删除 `JwtTokenInterceptor`、`BaseContext`、`CurrentUserUtil`。
- 新增：
  - `JwtAuthenticationFilter`：解析 Bearer Token、校验签名与过期时间、加载用户、校验状态和逻辑删除、写入 `SecurityContext`。
  - `AuthenticatedUser`：登录主体，携带用户 ID、用户名、角色、部门。
  - `SecurityUtils`：从 `SecurityContext` 读取当前用户。
- `SecurityConfig` 改为无状态会话：
  - 放行登录、注册、刷新 Token、Swagger/Knife4j 路径。
  - 未认证返回 401，无权限返回 403。
  - 开启方法级安全，Controller 使用 `@PreAuthorize`。
- `PermissionService` 统一资源级权限：知识库可见、可管理；文档、问答、工单据此校验。
- 用户、部门、统计、工单等管理接口加角色限制。
- 前端 `ProfileView`、`UserManage` 跟随接口/字段调整。
- 增加测试：
  - `JwtAuthenticationFilterTest`
  - `SecurityConfigTest`
  - `PermissionServiceTest`
  - `UserLoginServiceImplTest`
  - 测试辅助 `TestAuthentication`、`SecurityTestController`

**解决的问题**

| 问题 | 解决方式 |
| --- | --- |
| 用户上下文依赖拦截器 + ThreadLocal，跨层获取不便 | 改为 Spring Security `SecurityContext`，通过 `SecurityUtils` 获取 |
| 禁用/删除用户后旧 Token 仍可访问 | 每次请求从数据库重新加载用户并校验 `status`、`is_deleted` |
| 管理接口只靠前端隐藏入口 | 后端 `@PreAuthorize` 做接口级授权 |
| 知识库/文档/工单的权限判断分散 | 集中到 `PermissionService`，列表 SQL 也追加权限条件 |
| 401/403 语义不清晰 | Security 统一返回 401/403，前端分别处理 |

**遗留问题**

- Token 仍然无法主动失效，登出只清理前端和 `SecurityContext`。
- 没有引入 Redis 黑名单，Redis 依赖和配置实际未使用。
- 前端菜单没有按角色过滤，普通员工仍能看到管理入口。

## 7. 2026-11-20：当前工作区的未提交修复

本次文档任务开始前，工作区已有 4 个未提交的源码改动。为避免把无关改动混入文档提交，本次**不提交**这些文件，仅记录其内容。

### 7.1 `KnowledgeServiceImpl` 收藏逻辑

- 收藏切换由“只按用户查询最近一条”改为“按用户 + 知识库查询”。
- 插入收藏时显式设置 `userId`、`kbId`、`isDeleted=0`。
- 已存在记录时按当前状态取反，返回最新收藏状态。
- 修复了同一用户收藏多个知识库时可能取错记录、切换结果不正确的问题。

### 7.2 `DocumentMapper.xml` 文档列表权限 SQL

- 把 `kb.is_deleted = 0` 从 `WHERE` 移到 `LEFT JOIN ... ON`，避免知识库被删除后上传者连自己的文档也查不到。
- 可见性条件改为 `NULL` 安全的写法，保证知识库缺失时仍能按上传者/公开/部门规则返回。
- 查询列去掉 `d.*`，改为显式字段列表，避免实体字段与 SQL 列不一致。
- 当前仍存在 `kb_id` / `kbId` 参数名不一致的问题，按知识库筛选不生效，本次未修改。

### 7.3 `QaServiceImpl`、`JwtAuthenticationFilter`

- 仅做代码格式调整（换行、空行、链式调用排版），不改变业务逻辑。

## 9. 复盘

**做得好的地方**

- 主链路完整：上传、解析、分片、向量化、检索、问答、引用、反馈均有实际代码。
- 权限模型从“前端隐藏入口”升级为“后端接口授权 + 资源级授权”，并有对应测试。
- 关键第三方依赖都做了封装（MinIO、Embedding、Chat、Qdrant），便于替换。
- 文档清理前先备份，删除有依据，避免误删源码和配置。

**需要改进的地方**

- 删除链路缺少一致性设计：MySQL、MinIO、Qdrant 三者没有统一清理。
- 异步任务没有状态机、重试和补偿，失败后只能人工重新解析。
- 统计任务写了但没启用，属于“代码存在、功能未生效”。
- 文档与实现容易脱节；后续应把开发文档作为代码变更的一部分同步更新。
- 前端存在硬编码数据和未使用的接口封装，演示前应清理或标注。

**后续建议（按优先级）**

1. 补 `@EnableScheduling`，并让热门问题统计支持幂等重算。
2. 修复文档列表 `kbId` 参数名、补收藏表 DDL、修正 `updateDocumentTitle` 写入字段。
3. 为删除文档/知识库增加 MinIO 与 Qdrant 清理，或引入软删除后的异步清理任务。
4. 增加相似度阈值和检索结果排序，保证引用顺序与得分一致。
5. 补充文档解析、向量化、问答、统计的自动化测试。
6. 把 JWT 密钥和第三方 API Key 迁移到环境变量，收紧 CORS。
