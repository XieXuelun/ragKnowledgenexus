# RAG KnowledgeNexus 需求规格说明书

**文档版本：** v1.0  
**文档状态：** 需求评审稿  
**编制日期：** 2026-09-21  
**项目名称：** RAG KnowledgeNexus 企业智能文档问答系统  
**文档用途：** 明确系统建设目标、用户需求、功能范围、数据要求、非功能要求和验收标准，作为软件设计、开发和测试的共同依据。

## 1. 文档说明

### 1.1 编写目的

本文档用于回答以下问题：

1. 系统面向哪些用户，解决什么问题。
2. 系统需要提供哪些页面和业务功能。
3. 每类数据如何录入、修改、查询和删除。
4. 不同角色的权限边界是什么。
5. 系统在性能、安全、兼容性和可靠性方面需要达到什么水平。
6. 哪些结果可以作为项目验收依据。

### 1.2 项目范围

系统建设一个面向企业内部的知识库和智能问答平台，覆盖：

- 用户与部门管理。
- 角色和知识库权限管理。
- PDF、DOCX、TXT 文档上传、解析和预览。
- 文档分片、向量化和语义检索。
- 基于企业文档的大模型问答。
- 问答反馈和问题工单。
- 使用统计和热门问题分析。

### 1.3 术语定义

| 术语 | 说明 |
| --- | --- |
| 知识库 | 按业务主题组织的文档集合，也是向量检索的隔离单位 |
| 文档 | 用户上传到知识库的原始文件及其元数据 |
| 分片 | 将文档正文按语义和长度切分后形成的最小检索单元 |
| 向量化 | 通过 Embedding 模型将文本转换为固定维度向量 |
| RAG | 检索增强生成，先用知识库检索上下文，再交给大模型生成回答 |
| Top-K | 向量检索返回的候选片段数量 |
| 工单 | 用户将无法解决或需要人工处理的问题提交给管理员 |
| 可见范围 | 知识库对私有、部门和全员开放的范围 |

## 2. 项目背景与目标

### 2.1 项目背景

企业内部文档通常分散在个人电脑、共享目录和不同业务系统中，存在以下问题：

- 文档查找依赖文件名和关键词，无法理解自然语言问题。
- 文档更新后，阅读者难以快速定位最新内容。
- 通用大模型不了解企业私有知识，直接回答容易产生错误。
- 部门资料缺少合理的权限隔离。
- 问答效果、常见问题和使用趋势缺少统计。

### 2.2 建设目标

| 目标编号 | 建设目标 |
| --- | --- |
| G-01 | 建立统一的企业知识库和文档管理入口 |
| G-02 | 实现文档自动解析、分片、向量化和索引 |
| G-03 | 支持基于自然语言的文档问答和来源引用 |
| G-04 | 支持用户、部门、角色和知识库可见范围管理 |
| G-05 | 支持问答反馈、问题转工单和管理员处理 |
| G-06 | 支持知识库、文档和问答运营数据统计 |
| G-07 | 形成可部署、可维护、可扩展的前后端分离系统 |

### 2.3 成功判据

- 用户能够完成从注册登录到知识库问答的完整操作。
- 管理员能够完成用户、部门、知识库和工单管理。
- 文档上传后能够自动解析和建立索引。
- 问答结果能够给出知识库来源片段，而不是只依赖模型记忆。
- 不同角色和不同可见范围的数据相互隔离。
- 核心接口在预期负载下稳定运行，错误有明确反馈。

## 4. 业务范围

### 4.1 业务流程

```text
管理员初始化部门和用户
    ->
管理员或知识库管理员创建知识库
    ->
用户上传 PDF、DOCX、TXT 文档
    ->
系统解析文档并生成文本分片
    ->
系统调用 Embedding 模型生成向量
    ->
向量写入 Qdrant 并可供检索
    ->
用户创建对话并提问
    ->
系统检索相关片段并调用大模型生成回答
    ->
用户查看答案和引用来源
    ->
用户提交好评、差评或工单
    ->
管理员处理工单并查看统计数据
```

### 4.2 业务边界

本期系统包含：

- 账号、角色、部门和知识库权限。
- 文档上传、解析、预览和索引。
- 基于知识库的问答和反馈。
- 工单流转和基础统计。

本期不包含：

- 在线 Office 文档协同编辑。
- 文档审批和版本发布流程。
- 复杂多租户和计费。
- 图片 OCR、视频和音频知识库。
- 企业级单点登录和外部身份提供商。

## 5. 功能需求

### 5.1 账号与认证

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-AUTH-01 | 用户注册 | 用户名唯一；密码至少 6 位；公开注册用户固定为普通员工 |
| FR-AUTH-02 | 用户登录 | 校验用户名、密码和账号状态；成功后签发访问 Token |
| FR-AUTH-03 | Token 刷新 | 有效 Token 可以换取新 Token |
| FR-AUTH-04 | 用户登出 | 客户端删除 Token，服务端结束当前认证上下文 |
| FR-AUTH-05 | 获取个人信息 | 返回用户名、昵称、邮箱、角色、部门和头像 |
| FR-AUTH-06 | 修改个人信息 | 用户只能修改自己的昵称、邮箱和密码 |
| FR-AUTH-07 | 修改密码 | 必须校验原密码；新密码长度为 6-100 个字符 |
| FR-AUTH-08 | 上传头像 | 支持常见图片格式，上传后返回可访问地址 |

**验收标准**

- 用户名重复时注册失败并提示明确原因。
- 禁用用户无法登录，已登录 Token 失效。
- 用户修改他人资料时系统拒绝请求。
- 密码在数据库中不得明文保存。

### 5.2 用户管理

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-USER-01 | 用户分页查询 | 支持用户名、昵称、状态、角色和部门筛选 |
| FR-USER-02 | 启用或禁用用户 | 只有超级管理员可以操作 |
| FR-USER-03 | 删除用户 | 逻辑删除；删除后不能登录 |
| FR-USER-04 | 查看用户详情 | 显示基础资料、角色、部门和状态 |

**查询条件**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `keyword` | 文本 | 用户名或昵称 |
| `status` | 枚举 | 正常、禁用 |
| `role` | 枚举 | 超级管理员、知识库管理员、普通员工 |
| `deptId` | ID | 所属部门 |
| `page` | 整数 | 页码 |
| `pageSize` | 整数 | 每页条数，最大 100 |

### 5.3 部门管理

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-DEPT-01 | 查看部门树 | 支持无限级父子部门 |
| FR-DEPT-02 | 查看部门平铺列表 | 按排序值升序返回 |
| FR-DEPT-03 | 查看部门成员 | 显示部门内未删除用户 |
| FR-DEPT-04 | 创建部门 | 名称必填，父部门必须存在 |
| FR-DEPT-05 | 修改部门 | 不允许形成自循环或循环父子关系 |
| FR-DEPT-06 | 删除部门 | 存在子部门或成员时禁止删除 |

**数据录入要求**

- 部门名称不能为空。
- 父部门默认可选择根节点。
- 排序值用于同级部门展示顺序。
- 备注为可选说明。

### 5.4 知识库管理

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-KB-01 | 查看知识库列表 | 只返回用户有权查看的知识库 |
| FR-KB-02 | 查看知识库详情 | 显示名称、描述、创建者、可见范围和文档数量 |
| FR-KB-03 | 创建知识库 | 名称唯一；创建者自动成为知识库所有者 |
| FR-KB-04 | 修改知识库 | 超级管理员或所有者可以修改 |
| FR-KB-05 | 删除知识库 | 超级管理员或所有者可以操作；删除前需确认影响范围 |
| FR-KB-06 | 设置可见范围 | 支持私有、部门可见和全员可见 |
| FR-KB-07 | 收藏知识库 | 支持收藏和取消收藏 |
| FR-KB-08 | 查询知识库名称 | 只返回当前用户有权访问的名称 |

**知识库录入字段**

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| 名称 | 是 | 最大 100 字符，全局唯一 |
| 描述 | 否 | 最大 500 字符 |
| 图标 | 否 | 使用系统支持的图标标识 |
| 可见范围 | 是 | 私有、部门、全员 |
| 所属部门 | 部门可见时必填 | 必须为有效部门 |

### 5.5 文档管理

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-DOC-01 | 文档分页查询 | 支持知识库、标题、文件类型和解析状态筛选 |
| FR-DOC-02 | 上传文档 | 支持 PDF、DOCX、DOC、TXT；单文件最大 50 MB |
| FR-DOC-03 | 查看文档详情 | 显示文件名、类型、大小、解析状态和分片数 |
| FR-DOC-04 | 预览文档 | 使用临时授权地址打开原文件 |
| FR-DOC-05 | 修改文档标题 | 不得改变原始文件内容 |
| FR-DOC-06 | 删除文档 | 同时移除业务数据、分片和向量索引 |
| FR-DOC-07 | 重新解析文档 | 删除旧分片和旧向量后重新创建 |
| FR-DOC-08 | 查看知识库文档 | 返回指定知识库中有权访问的文档 |

**上传数据**

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 知识库 ID | 用户选择 | 目标知识库 |
| 文件 | 用户上传 | 原始文件 |
| 标题 | 系统生成或用户输入 | 默认取文件名 |
| 文件类型 | 系统识别 | pdf、docx、doc、txt |
| 文件大小 | 系统读取 | 用于限制和展示 |

### 5.6 文档解析与索引

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-PARSE-01 | 提取文档正文 | PDF 使用 PDFBox，DOCX 使用 Apache POI，TXT 使用 UTF-8 |
| FR-PARSE-02 | 文本清理 | 合并多余空白，保留段落语义 |
| FR-PARSE-03 | 语义分片 | 目标分片长度约 500 字符，相邻分片保留约 50 字符重叠 |
| FR-PARSE-04 | 记录分片状态 | 每个分片记录待处理、成功或失败 |
| FR-PARSE-05 | 生成向量 | 使用统一 Embedding 模型，维度为 1024 |
| FR-PARSE-06 | 写入向量库 | 按知识库创建 Collection，并按分片 ID 写入 |
| FR-PARSE-07 | 更新文档状态 | 解析、向量化、索引全部成功后才标记为可检索 |
| FR-PARSE-08 | 支持失败重试 | 解析或索引失败后可以人工触发重试 |

### 5.7 智能问答

| 编号 | 功能需求 | 业务规则 |
| --- | --- | --- |
| FR-QA-01 | 创建对话 | 必须选择有权访问的知识库 |
| FR-QA-02 | 提交问题 | 问题不能为空，默认检索 Top-5 |
| FR-QA-03 | 检索知识片段 | 只在所选知识库范围内检索 |
| FR-QA-04 | 生成回答 | 只根据检索到的上下文回答，资料不足时明确拒答 |
| FR-QA-05 | 返回引用来源 | 返回片段内容、文档信息和相似度 |
| FR-QA-06 | 查看对话列表 | 只返回当前用户自己的对话 |
| FR-QA-07 | 查看对话详情 | 显示历史问题和回答 |
| FR-QA-08 | 提交反馈 | 支持好评和差评，可附原因 |

**问答输入输出**

| 类型 | 字段 |
| --- | --- |
| 输入 | 知识库 ID、对话 ID、问题、检索数量 |

### 6.3 页面通用要求

- 页面必须根据角色隐藏无权使用的入口。
- 列表页面使用分页、筛选和空状态提示。
- 删除、禁用和重新解析等高风险操作必须二次确认。
- 表单提交前进行必填项和格式校验。
- 异步处理页面应显示处理中、成功和失败状态。
- 错误提示应说明原因，不显示技术堆栈。

## 7. 数据需求

### 7.1 核心业务数据

| 数据域 | 主要数据 |
| --- | --- |
| 用户与组织 | 用户、部门、角色、状态 |
| 知识库 | 知识库、所有者、可见范围、部门、收藏 |
| 文档 | 文件元数据、存储路径、解析状态、分片数量 |
| 文本与向量 | 分片内容、分片序号、向量 ID、向量状态 |
| 问答 | 对话、问题、回答、引用来源、反馈 |
| 工单 | 标题、描述、优先级、状态、回复、处理人 |
| 统计 | 日统计、热门问题 |

### 7.2 数据录入规则

- 用户、部门、知识库和文档必须有创建时间和逻辑删除标记。
- 文档必须关联有效知识库和上传用户。
- 分片必须关联文档和知识库。
- 问答消息必须关联对话和用户。
- 工单必须关联创建用户，并可选关联知识库或问答消息。
- 向量库中的每条向量必须包含知识库 ID、文档 ID、分片 ID。

### 7.3 数据查询要求

- 列表查询默认按创建时间倒序。
- 用户可按用户名、昵称、角色、部门和状态查询。
- 知识库名称和描述支持模糊查询。
- 文档支持文件名、类型、解析状态和知识库查询。
- 问答支持对话标题和对话时间查询。
- 工单支持状态查询。
- 统计支持日期范围和知识库查询。

### 7.4 数据保留与删除

- 用户、知识库、文档使用逻辑删除。
- 删除知识库时必须处理关联文档、分片、收藏和向量 Collection。
- 删除文档时必须处理分片和向量 Point。
- 原始文件是否删除由知识库管理策略决定，但默认应随文档删除。
- 审计日志至少保留 180 天。

## 8. 权限需求

### 8.1 可见范围

| 可见范围 | 规则 |
| --- | --- |
| 私有 | 仅知识库所有者可见 |
| 部门可见 | 所有者、同部门用户和超级管理员可见 |
| 全员可见 | 所有有效登录用户可见 |

### 8.2 权限规则

- 超级管理员拥有全局管理权限。
- 知识库管理员只能管理自己创建的知识库。
- 普通员工不能创建知识库。
- 文档上传、改名、删除和重解析要求具备知识库管理权限。
- 文档详情和预览要求具备知识库查看权限。
- 对话和反馈只能由所属用户访问。
- 工单只能由创建者、超级管理员或对应知识库管理员访问。
- 统计接口只允许超级管理员访问。

## 9. 非功能需求

### 9.1 性能

| 编号 | 要求 |
| --- | --- |
| NFR-PERF-01 | 普通分页查询在正常负载下响应时间不超过 500 ms |
| NFR-PERF-02 | 单文件最大 50 MB |
| NFR-PERF-03 | 文档上传接口不等待完整解析和向量化 |
| NFR-PERF-04 | 单次问答默认检索不超过 20 个分片 |
| NFR-PERF-05 | 大模型调用超时可配置，前端显示处理中状态 |
| NFR-PERF-06 | 向量检索按知识库隔离，避免全量扫描 |

### 9.2 安全

| 编号 | 要求 |
| --- | --- |
| NFR-SEC-01 | 密码使用 BCrypt 等不可逆算法保存 |
| NFR-SEC-02 | 业务接口默认要求认证 |
| NFR-SEC-03 | 管理员接口必须进行角色校验 |
| NFR-SEC-04 | 所有资源访问必须校验归属或可见范围 |
| NFR-SEC-05 | 生产密钥不得写入代码和普通配置文件 |
| NFR-SEC-06 | 上传文件必须校验扩展名、MIME 和文件头 |
| NFR-SEC-07 | 日志不得输出密码、Token 和完整 API Key |

### 9.3 可靠性与一致性

| 编号 | 要求 |
| --- | --- |
| NFR-REL-01 | 文档解析和向量化任务失败后可重试 |
| NFR-REL-02 | 删除、重解析操作必须保证数据库和向量库最终一致 |
| NFR-REL-03 | 外部模型调用失败时返回可理解的错误 |
| NFR-REL-04 | 定时统计任务失败后可重新执行且不产生重复数据 |

### 9.4 兼容性

| 编号 | 要求 |

| NFR-COMP-03 | 前端支持最新两个主版本的 Chrome 和 Edge |
| NFR-COMP-04 | API 使用 JSON 和 UTF-8 |

### 9.5 可用性与易用性

## 12. 验收条件

### 12.1 功能验收

- 用户可完成注册、登录、退出和个人资料维护。
- 超级管理员可维护用户和部门。
- 知识库管理员可创建和维护知识库。
- 用户可向有管理权限的知识库上传文档。
- 上传后系统可展示待处理、处理中和完成状态。
- 解析完成后问答可检索到文档内容。
- 问答回答包含来源片段。
- 用户可提交反馈和工单，管理员可处理工单。
- 超级管理员可查看每日统计和热门问题。

### 12.2 权限验收

- 未登录用户不能访问业务接口。
- 普通员工不能访问用户、部门和统计管理接口。
- 普通员工不能查看私有知识库和无权访问的文档。
- 用户不能查看、修改或反馈他人的对话和消息。
- 知识库管理员不能管理他人知识库。

### 12.3 数据验收

- 删除文档后，分片和向量索引不再可检索。
- 重新解析不会保留旧版本分片和向量。
- 文档状态只有在解析、向量化和索引全部成功后才是成功。
- 定时统计重复执行不会产生重复记录。

### 12.4 非功能验收

- 常规列表查询满足性能要求。
- 上传 50 MB 文件时请求不会长时间阻塞。
- 生产环境无明文密码和密钥。
- 外部服务异常时页面有明确错误提示。
- 主流浏览器下主要页面可正常使用。
